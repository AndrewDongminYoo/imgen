# imgen TUI 리뷰와 개선 우선순위

## 범위

이 문서는 2026-08-27에 `imgen`의 코드, README, 배포 상태, 현재 유사 도구를 검토한 결과를 기록합니다.
검토 목적은 제품의 차별점, 사용자 작업 흐름의 위험, 다음 구현 단위, 홍보 방향을 명확히 하는 일입니다.

## 제품 판단

`imgen`은 범용 이미지 생성기가 아니라 Codex 사용자의 시각 자산 반복 작업대입니다.
가치는 이미지 모델이나 터미널 그래픽 프로토콜 자체가 아니라 `초안 작성 → 인라인 미리보기 → 재생성 → 저장`을 하나의 키보드 중심 흐름으로 제공하는 데 있습니다.
따라서 제품 범위를 로컬 모델 워크플로 또는 전문 이미지 편집기로 넓히지 않습니다.

## 잘한 점

- Codex가 이미 만든 이미지를 갤러리에서 읽고, imgen이 생성한 결과에는 정확한 프롬프트를 기록합니다.
- 이전 Codex 이미지의 프롬프트를 추측으로 복원하지 않습니다.
- 참조 이미지는 터미널 paste 형태와 시스템 클립보드를 함께 처리하고, 전송 전에 썸네일로 보여 줍니다.
- 픽셀 프로토콜이 없는 터미널도 기능상 지원하며, `blocks` 미리보기의 한계를 화면에 알립니다.
- 프롬프트 보강 결과를 자동 생성에 사용하지 않고, 편집기에서 사용자가 확인하도록 합니다.
- 생성 중에는 중복 실행을 막고, 취소와 경과 시간을 제공합니다.

## 유사 도구와 비교

| 도구 범주 | imgen의 장점 | imgen의 한계 |
| --- | --- | --- |
| Codex `exec` 스크립트 | 갤러리, 인라인 미리보기, 재생성, 저장을 한 화면에서 제공합니다. | 출력 속성은 여전히 에이전트 지시에 의존합니다. |
| OpenAI Images API | API 키와 별도 스크립트 없이 기존 Codex 인증을 사용합니다. | API가 제공하는 크기, 품질, 형식, 압축, 배경 제어를 노출하지 않습니다. |
| mflux | 모델 다운로드와 로컬 GPU 설정 없이 바로 Codex 작업 흐름에 연결합니다. | seed, steps, 해상도, 로컬 모델, 편집과 업스케일 같은 재현·제어 기능은 약합니다. |
| Chafa 등 터미널 뷰어 | 생성 맥락과 프롬프트 provenance를 이미지 탐색에 연결합니다. | 픽셀 렌더링 품질과 프로토콜 지원만으로는 차별화하기 어렵습니다. |

## 이번 구현 단위

- `s` 저장은 기존 파일을 덮어쓰지 않고 `-1`, `-2` 접미사를 붙입니다.
- 생성과 프롬프트 보강이 성공, 실패, 취소로 끝난 뒤 임시 작업 디렉터리를 정리합니다.
- 새 provenance는 프롬프트와 참조 이미지 경로를 함께 기록합니다.
- `r`은 기록된 이미지의 참조 이미지와 프롬프트를 다시 사용합니다.
- `prompts.json`은 임시 파일을 쓴 뒤 rename하여 완성된 JSON만 보이게 합니다.

## 남은 위험과 다음 구현 후보

1. 생성 결과를 전역 `~/.codex/generated_images`의 실행 전후 차이로 찾습니다.
   다른 Codex 이미지 생성 세션이 같은 시간에 끝나면 현재 프롬프트가 다른 결과에 귀속될 수 있습니다.
   다음 구현에서는 Codex 실행의 고유 세션 ID 또는 요청한 출력 파일을 기준으로 결과를 연결해야 합니다.
2. `imgen doctor`는 Codex 설치, `image_generation` 기능, 쓰기 가능한 설정 경로를 확인해야 합니다.
   자동화용 `imgen doctor --json`은 사람용 출력과 별도로 제공할 수 있습니다.
3. 좁은 터미널에서 단축키를 읽기 어려우므로 `?` 도움말 오버레이가 필요합니다.
4. 후보 A/B 고정 비교, 즐겨찾기, 저장 대상 폴더 선택은 반복 작업의 다음 가치가 될 수 있습니다.
5. 오래된 Codex 이미지의 프롬프트 backfill은 새 증거가 없으면 다시 시도하지 않습니다.
   현재 기록 방식과 도구 호출 형태가 세션마다 달라서, 추측한 라벨은 검색 결과를 오도할 수 있습니다.

## 홍보 방향

제품 메시지는 "또 하나의 이미지 생성기"가 아니라 "Codex 이미지 생성을 키보드 중심의 시각 반복 작업으로 바꾸는 도구"여야 합니다.
README 첫 화면에는 로고보다 `rough prompt → enhance → inline preview → reroll → save`를 보여 주는 짧은 실제 터미널 GIF가 적합합니다.
Homebrew 설치 경로를 개발용 `bun link`보다 먼저 안내해야 합니다.
대상 사용자는 이미 Codex로 앱 아이콘, 히어로 이미지, 게임 에셋을 만들지만 결과를 다시 찾고 비교하는 과정이 불편한 개발자입니다.

2026-08-27의 GitHub 조회에서 저장소는 별 0개, `v0.6.0` 릴리스 자산은 다운로드 2회였습니다.
이는 제품 실패의 근거가 아니라 배포·메시지 가설을 아직 검증하지 못한 초기 상태를 뜻합니다.

## 검증 경계

단위 테스트와 TypeScript 검사는 데이터 처리와 로컬 파일 동작을 검증합니다.
실제 터미널의 이미지 프로토콜, 키 입력, 클립보드 paste 동작은 실제 터미널에서 probe와 화면 확인으로 검증해야 합니다.
pty 캡처만으로 해당 동작을 판정하지 않습니다.
